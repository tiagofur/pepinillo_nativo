1. PRODUCTION DOCKER COMPOSE (docker-compose.prod.yml)
================================================================================

Path: /sessions/blissful-cool-fermat/mnt/pepinillo_nativo/backend/docker-compose.prod.yml

Components:
  • api service
    - Builds from Dockerfile (production-ready multi-stage build)
    - Restart policy: always
    - Depends on db and redis (with health checks)
    - Loads environment from .env.production
    - Port 8080 (internal only, exposed via Caddy)
    - Health check: GET /api/v1/health

  • db service (PostgreSQL 16)
    - Image: postgres:16-alpine
    - Persistent volume: postgres_data
    - Health check: pg_isready
    - Internal port: 5432 (only accessible within network)
    - Logging: JSON format, 10MB max-size, 3 files rotation

  • redis service (Redis 7)
    - Image: redis:7-alpine
    - Persistent volume: redis_data with AOF enabled
    - Health check: redis-cli ping
    - Internal port: 6379 (only accessible within network)
    - Logging: JSON format, 10MB max-size, 3 files rotation

  • caddy service (Reverse Proxy)
    - Image: caddy:2-alpine
    - Exposes ports: 80 (HTTP), 443 (HTTPS)
    - Reverse proxies to api:8080
    - Automatic Let's Encrypt SSL certificates
    - Persistent volumes: caddy_data, caddy_config
    - Logging: JSON format, 10MB max-size, 3 files rotation

Network:
  - Internal bridge network: pepinillo-network
  - Services communicate internally, no direct external access to db/redis

Volumes:
  - postgres_data: Database persistence
  - redis_data: Redis AOF persistence
  - caddy_data: Let's Encrypt certificates
  - caddy_config: Caddy configuration

Test Job:
  - Ubuntu latest
  - PostgreSQL 16-alpine (test database)
  - Redis 7-alpine
  - Go 1.24 with test suite
  - Runs: go test -race -count=1 ./...

Deploy Job:
  - Requires: test job passes
  - Environment: production (GitHub environment protection)
  - Runs on: ubuntu-latest
  
  Steps:
    1. Checkout code
    2. SSH into VPS (using SSH_HOST, SSH_USER, SSH_KEY, SSH_PORT secrets)
    3. Pull latest code from main
    4. Build docker image: docker compose build api
    5. Start services: docker compose up -d
    6. Wait for services: db, redis, api to become healthy
    7. Health check: curl /api/v1/health (30 retries, 2s interval)
    8. On success: deployment complete
    9. On failure: attempt automatic rollback

Rollback Logic:
  - Saves previous image tag before deployment
  - If health check fails, restores previous image
  - Prevents broken deployments from staying live

GITHUB ACTIONS SECRETS (Required Configuration)
================================================================================

Navigate to: GitHub Repository → Settings → Secrets and variables → Actions

Required Secrets:

  SSH_HOST
    Value: VPS IP or domain
    Example: api.ppn.creapolis.dev or 192.168.1.100
    Purpose: SSH destination host

  SSH_USER
    Value: SSH username on VPS
    Example: deploy
    Purpose: SSH login username

  SSH_KEY
    Value: Private SSH key content (Ed25519 recommended)
    Example: -----BEGIN OPENSSH PRIVATE KEY-----...
    Purpose: SSH authentication
    Note: Use: cat ~/.ssh/pepinillo-deploy

  SSH_PORT (Optional)
    Value: SSH port number
    Default: 22
    Example: 2222
    Purpose: Custom SSH port (if configured on VPS)

Security Notes:
  - Keys never appear in logs (GitHub masks secrets)
  - Only use with SSH key-based auth (not passwords)
  - Rotate keys periodically
  - Restrict SSH key to deployment operations only

DEPLOYMENT WORKFLOW
================================================================================

Step 1: LOCAL MACHINE - Generate SSH Keys
  ssh-keygen -t ed25519 -f ~/.ssh/pepinillo-deploy -C "pepinillo-api-deploy"
  ssh-copy-id -i ~/.ssh/pepinillo-deploy deploy@api.ppn.creapolis.dev

Step 2: GITHUB - Configure Secrets
  GitHub Repo → Settings → Secrets → Add SSH_HOST, SSH_USER, SSH_KEY, SSH_PORT

Step 3: VPS - Run Setup Script
  ssh deploy@api.ppn.creapolis.dev
  sudo /opt/pepinillo-api/backend/scripts/vps-setup.sh

Step 4: VPS - Configure Environment
  Edit /opt/pepinillo-api/backend/.env.production
  Add all production secrets and service credentials

Step 5: VPS - Start Services
  cd /opt/pepinillo-api/backend
  docker compose -f docker-compose.prod.yml up -d

Step 6: LOCAL - Verify Health
  curl https://api.ppn.creapolis.dev/api/v1/health

Step 7: LOCAL - Test Automatic Deployment
  Make small change to backend/
  git push origin main
  Monitor GitHub Actions tab
  Verify: curl https://api.ppn.creapolis.dev/api/v1/health
